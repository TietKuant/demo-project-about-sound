# Audio Router V5 Data Contract

## Purpose

Audio Router V4 is a useful baseline, but local real-audio validation showed domain shift and overconfident wrong predictions. V5 is needed so the router can be evaluated as an academic audio-pattern detector instead of only a source-shaped classifier.

The V5 router should predict content evidence and then feed a conservative decision layer. It should not directly run processors without user or planner confirmation.

## Labels

- `speech_clean`: speech with no meaningful noise problem.
- `speech_noisy_general`: speech with broad background noise where `clean_voice` is the likely route.
- `speech_target_noise`: speech mixed with a project-supported target noise class such as dog bark, car horn, or siren.
- `music_with_vocals`: music mixture with likely vocals.
- `environment_only`: environmental sound without a speech or music processing target.
- `unknown_or_manual_required`: ambiguous or conflicting input that should not be auto-routed.

## Manifest Columns

The V5 manifest should use these columns:

```text
path,label,source_corpus,source_id,recording_id,split,is_synthetic,mix_clean_source,mix_noise_source,snr_db,route_target,engine_target,duration_sec,notes
```

Field meanings:

- `path`: audio or media file path.
- `label`: one of the V5 content labels.
- `source_corpus`: dataset or private holdout source name.
- `source_id`: source clip or dataset item identifier.
- `recording_id`: grouping key for split safety.
- `split`: train, val, test, or holdout.
- `is_synthetic`: whether the row was generated by mixing.
- `mix_clean_source`: clean speech source id for synthetic mixtures.
- `mix_noise_source`: noise source id for synthetic mixtures.
- `snr_db`: synthetic mix SNR when known.
- `route_target`: conservative route target proposed by taxonomy.
- `engine_target`: processor family associated with the route.
- `duration_sec`: probed duration.
- `notes`: short audit notes.

## Source-Confounding Risk

Source-disjoint splitting is necessary but not sufficient. If each label maps to one corpus, the model can learn corpus artifacts rather than audio semantics. For example, `music_with_vocals` from one music corpus and `environment_only` from two environmental corpora can still create source fingerprints.

V5 must report per-source metrics and evaluate whether errors increase when a source is held out.

## Evaluation Protocol

V5 evaluation should include:

1. Normal split: basic train/validation/test evaluation.
2. Source-disjoint split: prevent identical recordings or source clips crossing splits.
3. Leave-one-source-out: train without one source corpus and test on it.
4. Real-audio holdout: local private audio reported only in aggregate.
5. Risk-coverage / accepted accuracy: measure accuracy only on predictions accepted above the confidence threshold.
6. Dangerous-route count: count accepted predictions that would route clean speech or environment-only audio to an unsafe processor.

## Recommended Direction

V5 should use frozen pretrained audio embeddings with a lightweight classifier head and a conservative abstain decision layer. Handcrafted features can remain as audit features, but they should not be the only representation used for routing claims.

DeepFilterNet, Demucs, and the target-noise suppressor remain processors. The router should recommend or abstain; it should not be described as a production auto-router.
